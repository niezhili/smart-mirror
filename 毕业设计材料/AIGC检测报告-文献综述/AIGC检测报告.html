三、语音交互关键技术研究现状

国内方面，随着智能家居生态的成熟，智能镜产品逐步进入浴室、美妆与服装零售等场景，各类“智能魔镜”“智能化妆镜”商用产品不断涌现。在高校与研究层面，多数工作基于树莓派等单板计算机与 MagicMirror² 框架进行二次开发，重点集中在信息展示定制与简单语音控制上。总体来看，现有智能镜面系统大多停留在“信息展示+简单指令控制”阶段，将大语言模型、人脸识别、多模态感知深度融合进镜面终端的研究仍较少，交互的自然度与智能化水平有较大提升空间。 95.3%
唤醒词检测（Keyword Spotting）通常在本地持续监听特定关键词，其挑战在于误唤醒率与功耗的平衡：唤醒模型需要全天候运行，过灵敏会造成误唤醒和隐私顾虑，过迟钝则影响首次交互体验。目前常用的做法是将轻量唤醒模型与 VAD 级联，先由 VAD 过滤静音段再进行关键词判决，并引入连续多帧确认与冷却时间等防抖策略，在保证唤醒率的同时降低无效识别带来的资源消耗。此外，唤醒与 VAD 环节尽量在端侧本地完成，也有助于减少音频数据上云带来的隐私风险。 95.3%
Transformer 结构[1]的提出奠定了大语言模型（LLM）的基础。以 GPT 为代表的自回归语言模型证明了规模化的价值，此后 Qwen[2]、DeepSeek 等模型在中文理解、多语言能力与推理水平上不断进步，并通过开放 API 的方式降低了应用接入门槛。综述研究[5]指出，大语言模型已具备多轮上下文对话、指令遵循与角色扮演能力，可以承担智能设备的“对话大脑”。 94%
语音合成（TTS）从早期的拼接合成与参数合成，发展到基于深度神经网络的波形生成，自然度已接近真人水平。当前的云端 TTS 服务（如火山引擎、百度智能云）普遍支持多语种、多音色与情感风格控制，并采用 WebSocket 流式接口，可以边生成边播放。对于智能镜面这类交互终端，将长句按标点分段流式合成与播放，能有效压缩用户感知延迟，是提升对话体验的关键工程手段。 94%
从会议或谈话录音中自动提取待办事项，学术上属于会议内容理解的研究范畴。AMI 会议语料库[16]提供了多通道录音、转写与标注数据，是该方向的经典评测基础；QMSum[17] 进一步提出基于查询的多域会议摘要任务，推动了对长转写文本要点抽取的研究。相关工作表明，将长转写按语义分段后交由大语言模型进行结构化抽取（待办、日程、提醒、纪要等类别），比传统规则方法具有明显更高的准确率与泛化能力。 92.1%
系统架构方面，受算力约束，嵌入式 AI 终端普遍采用“端云协同”模式：本地负责传感器采集、VAD、人脸识别等轻量计算，云端负责 ASR、LLM、TTS 等重计算任务，两者通过网络衔接。这种架构兼顾了响应速度、识别质量与设备成本，是当前智能语音硬件的主流方案。 96.9%

但现有研究仍存在以下不足：一是多数智能镜面仅实现简单语音指令，缺少基于大语言模型的多轮自然对话与工具调用能力；二是语音交互链路的端到端延迟优化研究不足，影响实际体验；三是身份识别与对话系统往往相互独立，个性化服务难以落地；四是从谈话录音到可执行任务的自动化处理链路，在面向个人场景的智能终端上仍缺少完整实践。 96.9%

语音交互的第一环是判断“用户是否在说话”。传统的语音活动检测（VAD）依赖能量阈值与过零率等手工特征，在噪声环境下性能明显下降。近年来，基于深度学习的 VAD 成为主流，其中 Silero VAD[9] 是典型的轻量级预训练模型，单模型体积小、推理快，可以直接在树莓派等嵌入式设备上本地运行，为资源受限终端提供了可靠的人声检测能力。 57.7%

随着人工智能与物联网技术的快速发展，人机交互方式正从键盘、鼠标、触摸屏等传统手段，向语音、视觉等更自然的方式演进。镜面是人们在盥洗、更衣、出门前高频接触的界面，将其与显示屏、传感器和智能算法结合，就形成了智能镜面（Smart Mirror）这一新型交互终端。智能镜面能够在用户照镜的同时展示时间、天气、新闻等信息，并通过语音和视觉感知与用户交流，是智能家居场景中极具代表性的嵌入式人工智能应用。 15.8%
国外方面，智能镜面较早以创客项目和概念产品的形式出现。开源框架 MagicMirror²[10] 由 Michael Teeuw 发起，采用模块化架构，开发者可以像安装插件一样组合时钟、天气、日历、新闻等显示模块，目前已形成活跃的国际社区，是绝大多数智能镜面研究与二次开发的原型基础。在产业界，三星、松下等公司先后在国际消费电子展（CES）上展出智能镜子概念产品，将增强现实、健康检测等功能引入镜面形态；相关研究还探索了智能镜在皮肤分析、体重管理等健康监测场景中的应用。 15.4%
语音识别（ASR）经历了从 GMM-HMM 到 DNN-HMM 混合系统，再到端到端深度模型的演进[6][7][11]。端到端模型免去了人工设计的发音词典与决策树，主流路线包括 CTC、注意力机制与 Transducer 等。 28.5%
在效率方面，Paraformer[3] 提出非自回归的并行预测结构，在保持识别精度的同时显著降低推理时延，适合对实时性要求高的交互场景；在鲁棒性方面，Whisper[4] 利用大规模弱监督数据训练，在中英文等多语种、多口音场景下表现出很强的泛化能力。 18.3%
对嵌入式终端而言，直接本地部署高精度 ASR 仍然困难，因此通过云端 API（如阿里云 DashScope、百度智能云）调用大规模识别模型，成为当前智能硬件产品的普遍做法。 18.1%
在智能镜面场景中，将用户语音经 ASR 转写后交给 LLM 理解与生成，再由 TTS 播报，即可获得远超固定模板问答的自然对话体验；结合人设配置与多轮上下文管理，还能实现个性化、多语种的助手形象。 18.5%
单纯对话之外，研究者进一步提出了大语言模型智能体（LLM Agent）的概念：以模型为“大脑”，通过工具调用感知环境、执行动作。ReAct[13] 将推理轨迹与行动交织，让模型边思考边调用外部工具，显著提升复杂任务的完成率；Toolformer[14] 证明模型可以在自监督条件下学会在合适位置插入 API 调用。 29.4%
综述研究[15]将智能体的基本结构归纳为“规划—记忆—工具使用”三个模块，成为当前端侧与云端 Agent 应用的通用设计范式。在工程实现上，函数调用（Function Calling）通过让模型输出结构化的调用参数而非自然语言，保证了工具执行的确定性；配合单次请求工具调用轮数上限与解析失败回退策略，可以约束小模型误调用带来的风险。 21.6%
在部署侧，模型量化技术与 llama.cpp 等推理框架的成熟，使 0.5B—2B 级模型可以在树莓派等资源受限设备上本地常驻运行，为离线场景下的工具调用与简单对话提供了可行路径。 28.2%
工程实践中，录音采集与转写通常由成熟的商业平台完成（如飞书妙记等会议转写服务，提供开放 API 供增量拉取转写结果），研究重点集中在转写文本的下游处理——即如何可靠地将非结构化谈话内容映射为可执行的任务条目，并交由用户确认后落地，以控制自动抽取的误判风险。 39.2%
树莓派（Raspberry Pi）是目前应用最广泛的单板计算机之一，具备 GPIO 通用接口、多媒体处理与网络通信能力，且拥有完善的操作系统与软件生态，非常适合智能硬件原型验证。在感知层面，dlib[8] 提供了基于深度度量学习的人脸特征编码方法，将人脸映射为 128 维特征向量进行比对，在常规硬件上即可获得较高的识别精度，广泛用于嵌入式身份识别。 18.5%
